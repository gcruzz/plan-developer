Ruta de Ronald

Un camino para aprender el oficio de construir software a mano, entender cada capa, y al final usar la IA con el criterio de alguien que sabe lo que está pidiendo.

Antes de empezar, Ronald

Hoy la IA genera código en segundos. Eso no hace menos valioso aprender a programar; lo hace más valioso. Quien sabe construir software a mano entiende por qué algo funciona, detecta cuando la IA se equivoca y sabe qué pedirle. Quien no, copia y pega hasta que algo se rompe y no sabe por qué. Este plan te forma para ser el primero.

No te compares con tus compañeros. Todos los que "saben más" empezaron sin saber nada. Tu única medida es tu yo de hace un mes, y para eso vas a tener tu bitácora en GitHub: en cada reunión vamos a mirar hacia atrás y ver cuánto construiste.

Son unos dos años a 8–10 horas por semana. Si una fase te toma más, está bien. Lo único que no se negocia es la constancia.

Tu ritmo

El plan está pensado para unas 9 horas por semana: cada "semana" del plan son unas 9 horas de trabajo. Elige cuántas horas puedes dedicar de verdad, sin forzarte, y el plan te dice cuánto te toma cada fase. Lo puedes cambiar cuando quieras.

Recorre el plan con el botón Siguiente, de a una pantalla. Puedes saltar a cualquier paso desde la barra de arriba. La versión oficial, siempre actualizada, está en gcruzz.github.io/plan-developer.

Tu computadora · consúltala cuando la necesites

Tu computadora con Windows

Todo el plan funciona en Windows. Algunos profesores de los cursos usan Mac o Linux, así que aquí tienes cómo instalar cada programa en Windows y cómo traducir sus comandos. No instales todo de una vez: instala cada cosa cuando llegues a la fase que la necesita. Cada fase te avisa.

Dos consejos antes de empezar

  • Crea tu carpeta de proyectos fuera de OneDrive. OneDrive intenta sincronizar miles de archivos que crean los proyectos (como .venv o node_modules) y todo se vuelve lento o falla. Usa C:\Users\TuNombre\proyectos.
  • Haz que el explorador muestre las extensiones de archivo. En el Explorador de archivos: Ver → Mostrar → Extensiones de nombre de archivo. Así distingues index.html de index.html.txt.

Instalación paso a paso

Git y Git Bash · fase 0Ocultar
  1. Descarga el instalador de git-scm.com o usa winget install Git.Git.
  2. En el instalador, deja todo como viene, salvo dos pantallas: en Choosing the default editor (editor por defecto) elige Visual Studio Code, y en Adjusting the name of the initial branch (nombre de la rama inicial) elige Override y escribe main.
  3. Al terminar, busca Git Bash en el menú Inicio. Es una terminal donde funcionan los mismos comandos que en Mac y Linux: ls, cd, mkdir, touch.
  4. Configura los saltos de línea para que Git no te muestre avisos raros:
git config --global core.autocrlf true
VS Code · fase 0Ocultar
  1. Instálalo de code.visualstudio.com. En el instalador, marca Agregar "Abrir con Code" en el menú contextual y Agregar a PATH.
  2. Instala estas extensiones desde el ícono de cuadritos de la izquierda: Spanish Language Pack (VS Code en español), Python (de Microsoft) y, desde la fase 5, Live Server.
  3. Haz que la terminal de VS Code use Git Bash: Ctrl+Shift+P → escribe Terminal: Select Default Profile → elige Git Bash. Abre la terminal con Ctrl+ñ (o Ctrl+`).
Python y entornos virtuales · fase 2Ocultar
  1. Descarga Python de python.org. En la primera pantalla del instalador marca la casilla "Add python.exe to PATH". Si te la saltas, Windows no va a encontrar Python.
  2. Comprueba en una terminal nueva con python --version. Si se abre la Microsoft Store, ve a Configuración → Aplicaciones → Configuración avanzada de aplicaciones → Alias de ejecución de aplicaciones y apaga los dos de Python.
  3. Los cursos que usan Mac escriben python3 y pip3. En Windows escribe python y pip.
  4. Crear y activar un entorno virtual cambia según la terminal:
# Crear (igual en todas)
python -m venv .venv

# Activar en Git Bash
source .venv/Scripts/activate

# Activar en PowerShell
.venv\Scripts\Activate.ps1

# En Mac o Linux (lo que verás en algunos videos)
source .venv/bin/activate

Si PowerShell dice que la ejecución de scripts está deshabilitada, ejecuta esto una sola vez y vuelve a intentar:

Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
Node.js · fase 5Ocultar
  1. Instala la versión LTS (la estable) de nodejs.org o con winget install OpenJS.NodeJS.LTS.
  2. Comprueba con node --version y npm --version en una terminal nueva.
  3. Si PowerShell bloquea npm con un error de scripts, usa el mismo comando Set-ExecutionPolicy de la sección de Python, o trabaja en Git Bash.
PostgreSQL y pgAdmin · fase 6Ocultar
  1. Descarga el instalador para Windows desde postgresql.org (versión 17).
  2. Deja marcados PostgreSQL Server, pgAdmin 4 y Command Line Tools.
  3. Te va a pedir una contraseña para el usuario postgres. Anótala: la vas a necesitar siempre. Deja el puerto 5432.
  4. Para usar psql desde la terminal, agrega C:\Program Files\PostgreSQL\17\bin a la variable PATH: busca "variables de entorno" en el menú Inicio → Variables de entorno → Path → Editar → Nuevo.
  5. Comprueba con psql -U postgres. Si te pide la contraseña y entras, funciona. Sal con \q.
WSL2 y Docker Desktop · fase 9Ocultar

WSL2 es un Linux real que corre dentro de Windows. Muchas empresas trabajan así, y Docker en Windows lo necesita.

  1. Abre PowerShell como administrador (clic derecho → Ejecutar como administrador) y escribe wsl --install. Reinicia la computadora.
  2. Al volver, se abre Ubuntu y te pide un usuario y una contraseña de Linux. Pueden ser distintos a los de Windows.
  3. Instala Docker Desktop desde docker.com o con winget install Docker.DockerDesktop. En la instalación, deja marcado Use WSL 2 instead of Hyper-V.
  4. Abre Docker Desktop y espera a que diga que está corriendo. Comprueba con docker run hello-world.
  5. Si aparece un error de virtualización, hay que activarla en la BIOS de la computadora (busca el modelo de tu computadora + "activar virtualización"). Pide ayuda a tu mentor si no sabes cómo.
Claude Code · fase 12Ocultar

Problemas comunes en Windows

  • "python no se reconoce como un comando"Python no está en el PATH. Reinstálalo marcando "Add python.exe to PATH" y abre una terminal nueva.
  • "La ejecución de scripts está deshabilitada en este sistema"PowerShell bloquea scripts por seguridad. Ejecuta una vez Set-ExecutionPolicy -Scope CurrentUser RemoteSigned.
  • Git muestra "LF will be replaced by CRLF"Es solo un aviso sobre saltos de línea. Con git config --global core.autocrlf true desaparece.
  • Un programa recién instalado "no existe"Cierra y vuelve a abrir la terminal (y VS Code). La terminal solo ve los programas que existían cuando se abrió.
  • Todo va lento o hay archivos en conflictoSeguramente tu proyecto está dentro de OneDrive. Muévelo a C:\Users\TuNombre\proyectos.
  • Docker no arrancaRevisa que WSL2 esté instalado (wsl --status) y que la virtualización esté activada en la BIOS.
  • El antivirus bloquea algoA veces Windows Defender frena instaladores o scripts nuevos. Si confías en el programa (lo descargaste de la página oficial), permítelo.

Lo primero: GitHub y tu bitácora

GitHub es donde vive tu trabajo y donde lo vamos a revisar juntos. Todo lo que construyas va ahí desde el primer día. Si no está en GitHub, no existe. Esta es la tarea de tu primera semana.

Semana 1: prepara tu GitHub

GitHub solo existe en inglés. Los nombres en negrita son el texto exacto de cada botón; al lado va lo que significa.

  1. Crea tu cuenta en github.com. Elige un usuario profesional (tu nombre, sin números raros): va a estar en tu currículum.
  2. Instala Git y VS Code. En Windows, sigue la sección "Git y Git Bash" y "VS Code" de la pantalla Windows.
  3. Mira uno de los cursos de Git de la fase 0 hasta la parte de commit y push.
  4. Configura Git con tu nombre y correo, y crea tu repositorio bitacora con los comandos de abajo. La primera vez que hagas push, Git abre el navegador para que inicies sesión en GitHub.

  5. Pon ese link en tu perfil de GitHub y en tu bitácora.

    La regla de oro con la IA
    
Primero a mano, después con IA

    
La IA cambia de rol a medida que avanzas. Usarla antes de tiempo es como usar calculadora antes de aprender a sumar: llegas al resultado sin entender nada.

    

      
Fases 0–5 · ProfesorSolo para que te explique conceptos o errores. Nunca que te escriba la solución. Cada línea la escribes tú.

      
Fases 6–11 · RevisorPrimero lo haces tú completo. Después le pides que revise tu código y te explique qué mejorar y por qué.

      
Fases 12–14 · CompañeroAhora sí delegas. Tú diseñas, especificas y revisas; la IA escribe. Tu criterio es lo que vale.

Cómo usar los proyectos de cada fase

    
Cada fase trae un proyecto de prueba, que es obligatorio, y dos proyectos propuestos de dificultad media. Haz el de prueba primero. Después elige al menos uno de los propuestos; si quieres más práctica, haz los dos. Cada proyecto que termines va a tu portafolio, y cada uno tiene su casilla para marcarlo.

    
Cada proyecto propuesto tiene un botón Ver qué tienes que hacer con todo el detalle: qué debe hacer el programa, un paso a paso sugerido, un ejemplo de cómo se ve funcionando, la lista de "listo cuando" y un reto extra para quien quiera ir más allá.

Para cuando sientas que no avanzas

    
    
      
  • Escribe el código, no lo copies.Aunque el video lo muestre, pausa y escríbelo tú. Tus dedos también aprenden.
    • 
      
  • La regla de los 20 minutos.Si llevas 20 minutos atascado, pide ayuda. Antes de eso, sigue intentando: ahí es donde se aprende.
    • 
      
  • Sal del "infierno de los tutoriales".Si viste tres videos seguidos sin escribir código propio, para y construye algo.
    • 
      
  • Mira hacia atrás, no hacia los lados.En cada reunión abre tu primer proyecto. Esa es la única comparación útil.
    • 
      
  • Termina proyectos feos.Uno terminado y feo enseña más que uno perfecto a medias.
    • 
      
  • Un tema a la vez.No cambies de lenguaje o framework porque alguien dijo que es mejor. Termina tu fase.
    • 
      
  • Si te atrasas, continúa.No intentes recuperar haciendo dos semanas en una. Sigue desde donde estás.

Después del plan

    
Si llegaste hasta aquí, ya no eres principiante. Eres un desarrollador que sabe construir a mano y que usa la IA con criterio.

    
    
      
  • Elige una dirección según lo que más disfrutaste: web, backend, datos o productos con IA, y profundiza ahí.
    • 
      
  • Participa en hackathons y comunidades de programación de tu ciudad o en línea. Ahí está la gente con la que vas a trabajar.
    • 
      
  • Busca prácticas o trabajos pequeños de freelance usando tu portafolio y tus proyectos como prueba.
    • 
      
  • Empieza a aprender inglés técnico. Mucha documentación y muchos equipos trabajan en inglés, y te abre más oportunidades.
    • 
      
  • Ahora te toca a ti: enséñale a alguien que esté empezando. Explicar es la mejor forma de dominar lo que sabes.
    •
